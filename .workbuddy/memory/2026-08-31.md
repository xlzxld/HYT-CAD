# 2026-08-31

## dt_start.lsp v2.8 → v2.9: 修复低版本 CAD「参数类型错误: stringp nil」

**症状**: 低版本 CAD(2007~2015)上 APPLOAD dt_start.lsp 正常, 执行 DTINSTALL 报
`; 错误: 参数类型错误: stringp nil`, 无任何中文提示, 安装中断。

**根因**(与 scripts_ansi 副本无关, 两份 dt_start.lsp 逻辑完全一致):
老版本 getvar 读"本版本不存在的系统变量"时**静默返回 nil**(并非抛异常)。
v2.6 只 catch 了抛异常那半边, nil 漏出后被喂进 strcat/strlen 即 stringp nil。
三个泄漏点:
1. `dt:st-trusted-add/-del` — TRUSTEDPATHS 2016+ 才有, 2007~2015 返回 nil →
   `(dt:st-path-list nil)` → `(dt:st-split nil ";")` → `(strlen nil)` 炸(**最可能的元凶**)
2. `dt:st-acadoc-path` / `dt:st-write-hook` 的 vl-mkdir — ROAMABLEROOTPREFIX(2006+)
   在 2005 及更早/部分国产 CAD 上返回 nil → `(strcat nil ...)` 炸
3. `dt:st-locate` — 无图纸打开时 DWGPREFIX 可能返回 nil → 同样 strcat 炸

**修复**:
- 新增兼容底座 `dt:st-gets`(取系统变量, 不可用一律返回 "")、`dt:st-hasvar`(变量是否存在)、
  `dt:st-support-root`(ROAMABLEROOTPREFIX → LOCALROOTPREFIX → "" 兜底)
- `dt:st-acadoc-path` 收 dir 参数; 支持根不可用时兜底把 acaddoc.lsp 写进脚本目录
- `dt:st-add-support` 加 front 参数 —— 兜底模式下必须把脚本目录顶到支持路径最前,
  否则 AutoCAD 只加载搜索路径里第一个 acaddoc.lsp, 兜底那份不生效
- DTINSTALL 顺序改为: 先加支持路径 → 再写钩子 → 再处理 TRUSTEDPATHS
- `dt:st-split` / `dt:st-trusted-*` / `dt:st-del-support` 补 null 与 old=nil 判空
- DTDBG 新增 `[0z]` 环境探测段(ACADVER + 五个系统变量可用性 + acaddoc.lsp 落点)

**新增工具**: `tools/check_sysvars.py` —— 系统变量 nil 泄漏静态门禁。
反向验证: 在 v2.8 上命中 5 处风险(3 个根因), v2.9 全过。

**发版三件套**(改任何 .lsp 后必跑, 顺序固定):
`python tools/check_lisp.py scripts/<f>.lsp` → `python tools/check_sysvars.py` →
`python tools/make_ansi.py`(生成并校验 GBK 副本)→ 重新打包 scripts_ansi.zip。

**坑**: Python zipfile 写中文文件名需确认 UTF-8 flag(0x800), 否则解压出
`╦╡├≈.txt` 乱码 —— 旧 scripts_ansi.zip 就有这问题, 本次重打已修。
